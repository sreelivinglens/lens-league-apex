Rescore Images with Missing Data
Re-runs scoring only on images where audit data is incomplete or missing — not a calibration tool. Does not touch photographs already evaluated with complete data. Scores are permanent records of performance at the time of submission; use Force Rescore on individual images only when a specific error is identified (wrong genre, corrupted EXIF, false AI flag). Uses API credits and may take several minutes.
Refresh AI Suspicion Scores
Re-runs AI detection only on all photographs evaluated. Does NOT change scores, tiers, or any other data. Run this after updating the detection prompt to backfill existing images. Images scoring ≥0.7 are automatically moved to needs-review.
Fix Beta Plan Labels
Updates all manually-activated beta users to monthly plan so MRR calculates correctly.
Reset All Peer Rating Credits & Data
Resets all users' rating_credits to 0 and clears all peer rating data — assignments, ratings, pool entries, blended scores. Cannot be undone.

Haiku Rescore — Single Image
Re-runs the Haiku evaluation engine on one specific Haiku image (is_haiku_try = TRUE) using the improved prompt with REPETITION BLOCKED constraint. Updates score, tier, and all text fields (impression, strength, next leap, what next, master reference).

When to run: Use this to test that the REPETITION BLOCKED fix is working before running bulk. Score one image, check the scorecard — impression should be distinctly different from previous scorecards for the same user. Also use this if a specific scorecard was generated before the 181.52 prompt fix and needs updating.

Enter the image ID below. Find it in the image tile above (shown as #ID) or from the URL /try/result/<id>.
Haiku Rescore — All Images for User
Re-runs the Haiku engine on all Haiku images for one user, oldest-first. This is critical — oldest-first ensures REPETITION BLOCKED accumulates correctly: image 2 sees image 1's new impression, image 3 sees 1+2, and so on. Each rescore is spaced 1 second apart to avoid API rate limits. Runs in the background — check Railway logs for progress ([haiku_rescore_user] user=X complete — N/N rescored).

When to run:
  • Before production merge — any beta user who did evaluations before Session 192 (2026-08-24) has scorecards generated without REPETITION BLOCKED. Run this for each beta user to clean their history before launch.
  • After a prompt fix — any time the Haiku prompt is updated and existing scorecards need to reflect the new quality.
  • On user complaint — if a user notices repetitive feedback across their scorecards, run bulk rescore for their user ID.
Do not run for users who are mid-evaluation (currently uploading) — wait until they are done.
